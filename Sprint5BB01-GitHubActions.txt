  - `flyctl deploy --remote-only` usa exatamente o mesmo mecanismo de
    builder remoto (Depot) que `flyctl deploy --build-only` usou nesta
    Sprint — o build bem-sucedido validado em
    Sprint5BB01-FlyBuild.txt e' uma prova direta de que o MESMO comando
    (variando so' a flag `--build-only` vs `--remote-only`, que apenas
    controla se o deploy e' publicado ou nao) funcionaria identicamente
    dentro do GitHub Actions.
  - Nenhum secret novo e' necessario: `FLY_API_TOKEN` (ja configurado)
    continua sendo o unico secret usado — nao ha' segredo de acesso a um
    segundo repositorio (hub-sdk), porque nao ha' segundo checkout.
